# Action1 optional add-on

Approved scope: administrator-configured, one-way Action1 device import into organization configurations, encrypted API credentials, connection testing, explicit organization mapping, stable external-ID matching, manual-documentation preservation, status/errors and Sync now. LAMP deployment and browser-only operation remain. No scripts, patch deployment or remote-control API actions.

Implementation: bundled optional add-on under Modules/Integrations/Action1, disabled by default; additive migration 003. One Action1 Enterprise per installation, US/EU region allowlist. AES-GCM credentials/tokens derived from existing application key. Fixed-origin HTTPS transport, no redirects or provider-supplied URL following. Paginated discovery and sync in durable browser-driven batches, shared request pacing and server-directed 429 retry delays. No cron required; unattended scheduling is outside this first connector.

Organizations are explicitly mapped to existing local organizations. Imported configurations use an integration-owned template and external_records keyed by connection/provider ID. Sync creates internal-only records; updates only owned fields, preserves names, notes, references, visibility and extra fields. Archived records are skipped and missing devices are retained. Mapping cannot move linked records into another organization. Template and batch changes are transactional with a global per-database add-on advisory lock. Full page validation precedes database writes; transient retries do not advance cursors. Credentials and response bodies never enter audit or errors.

Validation: fake HTTP transport tests for auth, pagination, rate limits, invalid bodies and origin rejection; DB tests for ciphertext, privileges, ID matching, local-field preservation, archive behavior and retry cursors; HTTP administrator/CSRF/upgrade tests; clean build and complete suite. No live Action1 tenant or credentials are available, so live validation must be done on the dev site before release.
